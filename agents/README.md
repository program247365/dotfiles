# Agents

Agent configuration for tools I use from this dotfiles repo.

The goal is the same across agents:

- Keep configuration in version control.
- Install with symlinks instead of copies.
- Make setup idempotent and scriptable.

## Quick Start

Run all installers in this repo:

```bash
~/.dotfiles/script/install
```

Or run only agent installers:

```bash
sh ~/.dotfiles/agents/claude/install.sh
sh ~/.dotfiles/agents/codex/install.sh
sh ~/.dotfiles/agents/pi/install.sh
sh ~/.dotfiles/agents/philosophy/install.sh
```

## Shared Philosophy

Canonical source:

- `agents/philosophy/SOFTWARE_ENGINEERING.md`

`agents/philosophy/install.sh` links this file to:

- `~/.dotfiles/SOFTWARE_ENGINEERING.md`
- `~/.claude/SOFTWARE_ENGINEERING.md`
- `~/.codex/SOFTWARE_ENGINEERING.md`

It also follows a future-friendly convention: any agent folder under `agents/<name>/` that has an `install.sh` gets a linked `~/.<name>/SOFTWARE_ENGINEERING.md`.

## How Instructions Load

Every agent gets two layers: **global** instructions (yours, every repo) and
**project** instructions (one repo). All three agents share one set of global
sources, and each repo has one shared `AGENTS.md`.

Global sources (edit these, nothing else):

- `agents/claude/home/CLAUDE.md`: behavior and the WORKLOG convention
- `agents/philosophy/SOFTWARE_ENGINEERING.md`: the philosophy
- `agents/claude/rules/*.md`: rules (search, kpr, git workflow, ...)

| | Claude Code | Codex | pi |
| :- | :- | :- | :- |
| **Global** | `~/.claude/CLAUDE.md` (symlink), which `@`imports the philosophy, plus `~/.claude/rules/` (symlink) | `~/.codex/AGENTS.md`, a **generated copy** of all three sources, minus `tool-use.md` | `shared-rules` extension reads the sources at session start, minus `tool-use.md` |
| **Project** | `AGENTS.md` from the working directory up, **only if** no `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` exists there (v2.1.277+) | `AGENTS.md` from the repo root down to the working directory | `AGENTS.md` from the working directory up |
| **Picks up edits** | Next session | **After regenerating** (see below) | Next session |

### Project instructions

Write a repo's instructions in `AGENTS.md`. Don't add a `CLAUDE.md`: if one
exists, Claude Code reads it *instead of* `AGENTS.md`. If a repo already has a
`CLAUDE.md`, put `@AGENTS.md` in it. Claude's "Project instructions" setting
(`/config`) can change this; it stays on the default, `claude-md-or-agents-md`.

This repo's own `AGENTS.md` is a committed file at the root, with no
`CLAUDE.md` beside it.

### Why Codex is different

Claude Code expands `@path` imports and loads a rules directory. pi runs code
(an extension) that can read any file. Codex does neither: it reads one
global `~/.codex/AGENTS.md` verbatim. So Codex gets a concatenated copy, built
by `agents/codex/generate-agents-md.sh`.

- The first line is a `<!-- Generated by ... -->` marker. Don't edit the
  file; edit the sources and regenerate.
- A copy goes stale when a source changes. Regenerate with:

  ```bash
  ~/.dotfiles/agents/codex/generate-agents-md.sh
  ```

  `dot` also regenerates it (via `agents/codex/install.sh`).
- A hand-written `~/.codex/AGENTS.md` (no marker) is moved to
  `AGENTS.md.bak.<timestamp>` rather than overwritten.
- `tool-use.md` is left out because it names Claude Code tools (Grep, Glob,
  Task) that Codex and pi don't have.

### Upgrading an existing machine

`dot` runs `migrations/2026-10-19-agents-md-project-instructions.zsh`, which
is safe to re-run:

- replaces an old `~/.dotfiles/AGENTS.md` symlink with the committed file;
- warns about any `CLAUDE.md`/`CLAUDE.local.md` that would hide `AGENTS.md`;
- regenerates `~/.codex/AGENTS.md` when Codex is installed (it used to be a
  symlink to a file that was never committed);
- runs `claude update` if Claude Code is older than 2.1.277.

`agents/pi/install.sh` removes the old, dangling `~/.pi/agent/AGENTS.md` link.

### Check what loaded

- Claude: `/memory` lists every instruction file, `AGENTS.md` included.
- Codex: `head -1 ~/.codex/AGENTS.md` shows the marker; ask Codex to quote a
  rule heading to confirm.
- pi: ask it to quote a rule heading.

## Claude Setup

`agents/claude/install.sh` manages:

- `~/.claude/CLAUDE.md` -> `~/.dotfiles/agents/claude/home/CLAUDE.md`
- `~/.claude/settings.json` -> `~/.dotfiles/agents/claude/home/settings.json`
- `~/.claude/statusline.sh` -> `~/.dotfiles/agents/claude/statusline.sh`
- `~/.claude/rules` -> `~/.dotfiles/agents/claude/rules`
- `~/.claude/agents/<name>.md` -> `~/.dotfiles/agents/claude/agents/<name>.md` (one link per file)
- `~/.claude/skills/<name>` -> `~/.dotfiles/agents/claude/home/skills/<name>` (one link per own skill)
- third-party skills listed in `agents/claude/skills.txt` (see below)
- `~/.dotfiles/.claude` -> `~/.dotfiles/agents/claude/project`

This keeps all Claude configuration in version control. Global settings (permissions, plugins, hooks) are symlinked directly — changes made interactively by Claude Code are tracked automatically.

### Skills and subagents

`~/.claude/skills` and `~/.claude/agents` are real directories holding links,
not links to this repo. Other installers write into them freely: the skills
CLI, the tldraw and Spark apps (tldraw-offline, use-spark), and claude.ai's
synced skills (`synced/`). Those stay machine-local and never land in git.

- **Your own skill:** add `agents/claude/home/skills/<name>/SKILL.md`, then run
  the installer to link it.
- **Someone else's skill:** add `<owner/repo>#<commit> <name>` to
  `agents/claude/skills.txt`, then run `dot`. On every machine, `dot` links or
  installs whatever on that list is missing, at the pinned commit. The pin is
  the version you reviewed; a fresh machine gets exactly that.
- **Upgrading:** don't use `npx skills update`, which moves skills past their
  pins. Read upstream's diff, change the commit in skills.txt, delete
  `~/.claude/skills/<name>`, and run `dot`.
- The installer prints a `[note]` for an installed skill that isn't on the
  list, or one installed at a different commit than its pin.

## Codex Setup

`agents/codex/install.sh` manages:

- `~/.codex/AGENTS.md`: generated, not linked, by `generate-agents-md.sh`. See [Why Codex is different](#why-codex-is-different).
- `~/.codex/skills/<skill-name>` -> `~/.dotfiles/agents/codex/skills/<skill-name>` (for each local skill directory)

Installer behavior:

- Creates missing `~/.codex` and `~/.codex/skills` directories.
- Is idempotent (safe to rerun).
- Links through `script/link.sh` (see the repo's AGENTS.md): a differing local file is saved as `*.pre-dotfiles.<timestamp>`.

## Pi Setup

`agents/pi/install.sh` manages:

- `~/.pi/agent/settings.json` -> `~/.dotfiles/agents/pi/home/settings.json`
- Global instructions: none on disk. The `shared-rules` extension injects the global sources into the system prompt. See [How Instructions Load](#how-instructions-load).
- `~/.pi/agent/presets.json` -> `~/.dotfiles/agents/pi/home/presets.json`
- `~/.kevin/bin/pi` -> symlinked to the global `pnpm` install of `@earendil-works/pi-coding-agent`

Installer behavior:

- Uses `pnpm add -g @earendil-works/pi-coding-agent`.
- Creates missing `~/.pi/agent`.

Local models (Ollama, LM Studio) are not set up by dotfiles; add providers to the machine-local `~/.pi/agent/models.json` if you want them.

## Add a Codex Skill

1. Create a new directory under `agents/codex/skills/`:

```bash
mkdir -p ~/.dotfiles/agents/codex/skills/my-skill
```

2. Add `SKILL.md`:

```bash
cat > ~/.dotfiles/agents/codex/skills/my-skill/SKILL.md <<'EOF'
---
name: my-skill
description: "What this skill does."
---

# My Skill

Instructions go here.
EOF
```

3. Re-run installer:

```bash
sh ~/.dotfiles/agents/codex/install.sh
```

## Keep Philosophy Up To Date

To ensure both agents always use the latest philosophy:

1. Edit only the canonical file:
   - `~/.dotfiles/agents/philosophy/SOFTWARE_ENGINEERING.md`
2. Commit and sync dotfiles as usual.
3. Re-run installers only when links are missing/broken or on new machines:
   - `~/.dotfiles/script/install`
   - or `sh ~/.dotfiles/agents/claude/install.sh && sh ~/.dotfiles/agents/codex/install.sh && sh ~/.dotfiles/agents/philosophy/install.sh`
4. Start a new Claude/Codex session to ensure updated guidance is loaded.

## Troubleshooting

- Broken symlink after moving dotfiles:
  - Re-run relevant installer script.
- Local file was replaced by installer:
  - Restore from its backup (`*.pre-dotfiles.<timestamp>`, or `*.bak.<timestamp>` from older installs).
- Skill not visible in Codex:
  - Confirm the skill folder contains `SKILL.md`.
  - Re-run `agents/codex/install.sh`.

## Home-server app onboarding

The shared `srv-ify` skill lives in `agents/claude/home/skills/srv-ify/`.
Claude discovers it through its existing skills link; pi loads it through the
claude-skills extension. `agents/codex/skills/srv-ify` links the same source,
and the Codex installer makes it available globally. Use it from an app repo
to adapt that app to the contract in the srv checkout (`docs/app-contract.md`).
